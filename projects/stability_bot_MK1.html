Project Overview

Stability Bot MK1 is a two-wheeled self-balancing robot designed to balance itself using a PID loop. The robot continuously measures body orientation using an inertial measurement unit (IMU) and dynamically adjusts motor output to maintain balance.

In the future, the project may serve as a platform for carrying objects, following waypoints, or remote control.

Design Goals

Control System Platform

Create a robotics firmware framework capable of implementing and testing increasingly advanced control algorithms ranging from PID control to future Kalman-filter-based state estimation, as well as manual control.

Rapid Iteration

Currently uses fully 3D printable components and modular electronics to allow quick mechanical and firmware revisions during development.

Hardware Architecture

The current prototype uses readily available components to validate balancing performance before committing to a fully integrated PCB. Future revisions will improve sensing accuracy, power delivery, and system integration.

Firmware Architecture

Real-Time Control

FreeRTOS tasks separate sensor acquisition, state estimation, motor control, and debugging functions. This architecture improves maintainability while ensuring deterministic timing for balancing operations.

Control Loop

The balancing controller currently uses PID feedback derived from IMU orientation estimates. Future revisions will explore Kalman filtering and more advanced state-space approaches.

PCB & Schematic Development

While the current prototype relies on modular electronics, development has begun on dedicated PCB hardware. Initial work focuses on validating BMI320 integration before designing a fully integrated control board.

The final PCB is planned to consolidate sensing, motor control, power distribution, and debugging interfaces into a single compact assembly.

Debugging & Challenges

Noisy IMU data

Early hardware setups with the MPU6050 on a breadboard revealed significant noise and instability in orientation estimates. After debugging and investigation, the problem was traced to the unstable friction fit connections, poor sensor fusion algorithms, and insufficient filtering. These casued noise in stationary angle estimates and signal dropoff during movement, making the robot difficult to balance.

Signal Dropout

IMU readings would intermittently drop out during movement, causing the robot to lose balance. This was traced back to 2 issues:
1. Watchdog timer resets due to blocking code in the main loop, which was resolved by optimizing the control loop and adding a small delay.
2. Unstable physical connections to the IMU, which will be resolved in future revisions with a custom PCB and improved mounting solutions.
